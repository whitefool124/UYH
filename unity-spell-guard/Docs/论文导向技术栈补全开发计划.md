# 论文导向技术栈补全开发计划

## 1. 文档目标

本文档用于指导《符印守卫》Unity 项目在论文阶段继续补全游戏本体技术栈。当前项目已经具备基本游戏闭环、三输入源抽象、动态手势识别、HUD、测试和性能监控基础。后续开发不应再扩大到联机、复杂后端、DOTS/ECS 或大规模深度学习训练平台，而应围绕论文所需的“可演示、可复现、可配置、可采集、可验证”继续补强。

本文档将待补功能分为 P0、P1、P2 三类：

- **P0**：必须补，直接影响论文第 5 章实现完整度和第 6 章实验数据。
- **P1**：建议补，提升项目工程成熟度和答辩说服力。
- **P2**：有时间补，用于增强完整游戏观感和扩展性。

## 2. 当前技术栈基线

当前项目已经具备以下基础：

| 技术栈 / 模块 | 当前状态 | 论文价值 |
|---|---|---|
| Unity 2022.3.62f2c1 | 已使用 | 游戏引擎与运行环境 |
| MediaPipe Unity Plugin | 已接入 | Native 摄像头手部关键点识别 |
| ExternalBridge / UDP | 已接入 | 外部视觉链路、离线回放、YOLO + MediaPipe 实验入口 |
| Mock 输入源 | 已实现 | 稳定演示、自动化测试、无摄像头兜底 |
| GestureFrame / GestureCommand | 已实现 | 输入抽象与玩法解耦 |
| Native / External 动态识别 | 已实现 | Swipe、Snap、PointToFist、BodyShift 等动态动作 |
| UGUI / HUD | 已实现 | 菜单、调试反馈、运行状态显示 |
| Unity Test Framework | 已使用 | EditMode / PlayMode 自动化测试 |
| GesturePerformanceMonitor | 已实现基础 | FPS、延迟、命令统计、CSV 实验数据 |
| Editor 工具 | 已实现基础 | 场景生成、训练集验证 |

后续补强应优先利用上述已有模块，不重写主架构。

### P0-1 实验结果导出与归档闭环

#### 目标

将 `GesturePerformanceMonitor` 和 Python benchmark 的输出固定到项目目录，形成论文可直接引用的 CSV 证据链。

#### 开发内容

1. 在项目根目录建立统一结果目录：

```text
unity-spell-guard/ExperimentResults/
```

2. 统一输出文件命名：

```text
gesture_performance_mock_<timestamp>.csv
gesture_performance_native_<timestamp>.csv
gesture_performance_external_<timestamp>.csv
yolo_mediapipe_benchmark_<timestamp>.csv
```

3. 补一个结果说明文件：

```text
unity-spell-guard/ExperimentResults/README.md
```

记录：

- 实验日期；
- Unity 版本；
- 输入模式；
- 测试设备；
- 摄像头；
- 运行时长；
- 使用的视频样本；
- CSV 字段解释。

4. 确认 Unity 内导出字段至少包含：

```text
session_id,mode,source,elapsed_seconds,total_frames,
average_fps,min_fps,average_frame_ms,p95_frame_ms,
external_packets,avg_packet_interval_ms,
avg_estimated_latency_ms,p95_estimated_latency_ms,
static_commands,motion_commands,
swipe_lr,swipe_rl,snap,point_to_fist,body_shift_left,body_shift_right
```

#### 验收标准

- `ExperimentResults/` 下至少存在 3 个 Unity 性能 CSV：Mock、Native、ExternalBridge。
- 至少存在 1 个 YOLO / MediaPipe benchmark CSV。
- README 能说明每个 CSV 如何产生。
- 论文第 6 章可以直接引用表格数据。

#### 论文写法

可写为：

> 系统内置实验数据导出模块，能够在不同输入模式下记录帧率、帧耗时、UDP 包间隔、估算延迟和手势命令触发次数，并将结果保存为 CSV 文件用于后续统计分析。

## 6. 不建议加入的技术栈

短期内不建议加入以下内容：

- DOTS / ECS；
- Netcode / 联机；
- 数据库或云后端；
- Addressables 远程资源；
- HDRP 或复杂渲染管线；
- 大规模 YOLO 训练平台；
- LSTM / Transformer 实时推理主线；
- 完整商业化关卡系统。

原因是这些内容会显著扩大范围，但对当前论文主题“动态手势轨迹跟踪与 Unity 交互闭环”的直接收益有限。
