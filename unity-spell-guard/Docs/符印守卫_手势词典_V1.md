# 符印守卫 手势词典 V1

## 一、词典目标

这份手势词典不是单纯罗列动作名称，而是用于统一《符印守卫》当前版本的输入语言，确保后续关卡、地图、移动、战斗和 UI 设计都建立在同一套手势定义上。

本词典的核心用途包括：

- 统一策划、程序和演示时的叫法
- 明确每个手势的主语义和适用场景
- 明确哪些手势属于基础输入，哪些属于高阶输入
- 为后续状态机、优先级和识别参数调试提供依据

## 二、使用原则

### 2.1 一个手势只定义一个主语义

同一个动作可以在不同状态下有不同解释，但必须有一个最核心的主语义，不能在设计层面从一开始就承担多个平级含义。

### 2.2 先确定场景，再解释动作

手势语义不能脱离场景。菜单中的 `OpenPalm` 与战斗中的 `OpenPalm` 可以不同，但这种差异必须由状态机控制，而不是由玩家猜测。

### 2.3 词典分为四层

当前词典按以下四层组织：

1. 系统层手势
2. 导航层手势
3. 战斗层手势
4. 高阶层手势

## 三、系统层手势词典

系统层手势用于菜单、选关、设置、教程、结算等非战斗操作，目标是稳定、易学、低误触。

### 3.1 Point

- 中文名称：指向
- 英文标签：Point
- 主语义：焦点控制
- 适用场景：主菜单、选关、设置、结果页
- 系统解释：用于指向按钮、节点或交互区域
- 搭配规则：与 `停留确认` 组合使用
- 设计原因：这是最直观的 UI 操作动作，用户容易理解“我指哪里，焦点就在哪里”

### 3.2 Dwell

- 中文名称：停留确认
- 英文标签：Dwell Confirm
- 主语义：确认
- 适用场景：所有系统层界面
- 系统解释：当 `Point` 在同一区域持续停留达到阈值后，触发进入、确认或激活操作
- 备注：这不是独立识别手势，而是一条交互规则
- 设计原因：比“比划确认手势”更稳，也更适合新手和答辩演示

### 3.3 OpenPalm Hold

- 中文名称：张掌停留
- 英文标签：OpenPalm Hold
- 主语义：返回 / 退出
- 适用场景：设置页、教程页、结算页、子界面
- 系统解释：在可返回页面中，检测到稳定张掌并保持达到阈值后，执行返回上一级
- 设计原因：张掌具有“停下”“退出当前状态”的自然语义，同时误触率相对较低

### 3.4 SwipeRightToLeft

- 中文名称：右向左挥动
- 英文标签：Swipe Right To Left
- 主语义：快捷返回
- 适用场景：设置页、结算页、部分二级页面
- 系统解释：在系统页面中作为高效返回动作使用
- 设计定位：可选快捷操作，不作为新手必学动作
- 设计原因：给熟练玩家一个更快的页面退出方式

## 四、导航层手势词典

导航层手势用于视角控制、地图推进和紧急换位，目标是让移动成为战斗和关卡的一部分，而不是独立负担。

### 4.1 Point

- 中文名称：指向
- 英文标签：Point
- 主语义：观察 / 瞄准
- 适用场景：自由移动、战斗中观察、地图推进
- 系统解释：根据手部视口位置控制视角转向
- 设计原因：延续“指向即控制方向”的一致语义，减少学习成本

### 4.2 Point High Hold

- 中文名称：高位指向保持
- 英文标签：Point High Hold
- 主语义：前进
- 适用场景：移动状态、走廊推进、接近目标点
- 系统解释：在 `Point` 状态下，当手位提升到设定阈值以上并保持时，触发缓慢前进
- 设计原因：不额外增加新手势，而是在现有 Point 基础上增加推进意图
- 风险提示：阈值必须稳定，否则容易把普通视角操作误判为推进

### 4.3 SwipeLeft

- 中文名称：左闪
- 英文标签：Swipe Left
- 主语义：向左短位移
- 适用场景：战斗中避让、换位、脱离近身威胁
- 系统解释：识别到向左短挥后，角色执行短距离左闪
- 设计定位：导航层高压动作
- 设计原因：满足“我需要立刻换位”这一战斗需求

### 4.4 SwipeRight

- 中文名称：右闪
- 英文标签：Swipe Right
- 主语义：向右短位移
- 适用场景：战斗中避让、换位、脱离近身威胁
- 系统解释：识别到向右短挥后，角色执行短距离右闪
- 设计定位：导航层高压动作
- 设计原因：和左闪共同构成最小闪避系统

### 4.5 Neutral / Hand Lost

- 中文名称：中立 / 丢手
- 英文标签：Neutral / Hand Lost
- 主语义：停止
- 适用场景：所有导航状态
- 系统解释：当没有明确导航意图或手离开识别区域时，角色停止推进，不做额外动作
- 设计原因：系统必须有安全默认状态，宁可少触发，也不要误触发

## 五、战斗层手势词典

战斗层手势用于基础施法，是所有玩家都应掌握的核心输入层。它们必须差异明显、识别稳定、适合确认机制。

### 5.1 Fist

- 中文名称：握拳
- 英文标签：Fist
- 主语义：攻击性结印
- 映射法术：火焰术
- 适用场景：基础战斗循环、清理普通敌、近距离反击
- 系统解释：识别为火焰术候选动作，保持稳定达到阈值后释放
- 设计原因：握拳天然具备力量感和攻击感，适合作为主输出输入

### 5.2 VSign

- 中文名称：V 手势
- 英文标签：VSign
- 主语义：控制性结印
- 映射法术：冰霜术
- 适用场景：处理冲刺敌、控场、拖延时间
- 系统解释：识别为冰霜术候选动作，保持稳定达到阈值后释放
- 设计原因：视觉形态与握拳、张掌差异明显，适合作为功能型法术输入

### 5.3 OpenPalm

- 中文名称：张掌
- 英文标签：OpenPalm
- 主语义：防御性结印
- 映射法术：护盾术
- 适用场景：保命、容错、穿越危险区、抵挡压力波次
- 系统解释：识别为护盾术候选动作，保持稳定达到阈值后释放
- 设计原因：张掌天然有“展开屏障”“阻挡”的语义，玩家容易形成直觉

### 5.4 Confirm Window

- 中文名称：施法确认窗口
- 英文标签：Confirm Window
- 主语义：静态手势确认机制
- 适用场景：所有基础法术
- 系统解释：识别到静态手势后，先进入候选状态，保持达到设定时长后正式施法
- 备注：这同样不是一个独立动作，而是一条战斗交互规则

## 六、高阶层手势词典

高阶层手势用于高压场景下的快速反应，不作为新手基础要求，而是作为输入熟练度和战斗节奏层的补充。

### 6.1 Snap

- 中文名称：弹指
- 英文标签：Snap
- 主语义：快速攻击触发
- 映射结果：快速火焰术
- 适用场景：紧急输出、敌人贴脸、打断高威胁目标
- 系统解释：识别到 Snap 后直接触发火焰术，不走完整静态蓄力流程
- 设计原因：Snap 非常适合承担“立刻出手”的高压语义

### 6.2 PointToFist

- 中文名称：指向转握拳
- 英文标签：Point To Fist
- 主语义：攻击衔接
- 映射结果：快速火焰术确认
- 适用场景：从观察瞄准快速切入攻击
- 系统解释：当玩家从 `Point` 快速过渡到 `Fist` 时，作为高阶攻击型输入识别
- 设计原因：这个动作天然符合“看到目标 -> 立刻施法”的节奏

### 6.3 SwipeLeftToRight

- 中文名称：左向右挥动
- 英文标签：Swipe Left To Right
- 主语义：快速控场
- 映射结果：快速冰霜术
- 适用场景：多目标压迫、需要立刻减速和争取空间时
- 系统解释：识别到明确横向动作后，直接施放冰霜术
- 设计原因：横向扫动具有“扩散控制”感，适合冰霜类法术

### 6.4 SwipeRightToLeft

- 中文名称：右向左挥动
- 英文标签：Swipe Right To Left
- 主语义：快速防御
- 映射结果：快速护盾术
- 适用场景：突然受压、即将吃伤害、需要立刻保命时
- 系统解释：识别到明确横向动作后，直接施放护盾术
- 设计原因：为高压场景提供不依赖静态确认的保命选项

## 七、手势优先级摘要

为了避免设计混乱，词典同时给出当前版本的解释优先级原则：

### 7.1 优先级总原则

1. 场景状态优先
2. 动态高阶动作优先
3. 系统层返回优先
4. 静态战斗手势确认优先
5. 导航输入优先
6. 无法确定时回退到 Neutral

### 7.2 重点冲突说明

#### Point 的冲突

- 在菜单中：Point = 焦点控制
- 在战斗中：Point = 视角控制
- 不允许 Point 直接承担基础施法语义

#### OpenPalm 的冲突

- 在系统页：OpenPalm Hold = 返回
- 在战斗中：OpenPalm = 护盾术
- 在导航中：默认不解释为返回，而是服从当前状态

#### Swipe 的冲突

- 系统页中：可作为快捷返回或设置切换
- 导航中：优先作为闪避
- 高阶战斗模式中：可映射快速法术

结论是：Swipe 不能在同一上下文里同时承担“闪避”和“快速施法”两个结果，必须依赖状态机做切换。

## 八、教学顺序建议

为了保证玩家不会因为词典复杂而退缩，建议按以下顺序教学：

### 8.1 第一阶段：系统层

- Point
- Dwell
- OpenPalm Hold

目标：先让玩家理解“这个游戏真的能不用键鼠完成操作”。

### 8.2 第二阶段：导航层

- Point 观察
- Point High Hold 前进
- SwipeLeft / SwipeRight 闪避

目标：让玩家理解空间控制与移动。

### 8.3 第三阶段：战斗层

- Fist
- VSign
- OpenPalm

目标：建立稳定的基础施法循环。

### 8.4 第四阶段：高阶层

- Snap
- PointToFist
- SwipeLeftToRight
- SwipeRightToLeft

目标：让熟练玩家体验更高效率的高压输入。

## 九、当前版本建议结论

当前版本的手势词典应控制在如下范围：

- 系统层：3 个核心定义 + 1 个快捷动作
- 导航层：2 个基础定义 + 2 个闪避动作 + 1 个安全默认状态
- 战斗层：3 个基础施法动作 + 1 条确认规则
- 高阶层：4 个快速动作

这套词典已经足够支撑：

- 全手势菜单导航
- 地图推进与选关
- 第一人称移动
- 三法术基础战斗
- 高压场景下的快速反应

## 十、总结

《符印守卫》手势词典 V1 的核心价值不在于“定义了多少动作”，而在于为整个项目建立了统一的输入语言。

只要这套词典被固定下来，后续的关卡设计、敌人设计、移动系统、UI 流程和程序实现都可以围绕同一套动作语义展开，项目就不会因为输入系统不断膨胀而失控。
