# 符印守卫：手势技术深挖

这份文档面向已经看过入门版的人。

目标不是“知道名词”，而是弄清楚：

- 每个技术到底解决什么问题
- 数学上在算什么
- 代码里具体在哪一层做的
- 为什么这些阈值和状态机能工作

---

## 1. 总体数据流

整个项目的手势链路可以压成这一条：

`摄像头/视频/UDP -> 关键点 -> 静态姿势 -> 动态动作 -> 命令 -> 意图 -> 游戏行为`

在代码里，对应大致是：

- 输入采集：`NativeMediapipeGestureRunner`、`UdpGestureReceiver`、`MockGestureInputProvider`
- 输入承载：`ExternalVisionFrame`、`GestureSnapshot`、`GestureFrame`
- 规则识别：`NativeMediapipeGestureRunner.ClassifyGestureFromLandmarks`
- 动态识别：`NativeMotionGestureRecognizer`、`ExternalMotionGestureRecognizer`
- 命令历史：`GestureCommandHistory`
- 意图映射：`GestureIntentMapper`
- 连招判断：`GestureSequenceMatcher`、`GestureComboTrigger`
- 自定义手势：`CustomGestureRecognizer`、`CustomGestureFeatureExtractor`、`CustomGestureTrajectoryMatcher`

## 2. MediaPipe 的底层思路

### 2.1 它不是“识别手势”，而是“输出结构化骨架”

MediaPipe Hands 的核心任务是：

1. 在图像中定位手
2. 输出 21 个关键点
3. 给出左右手标签
4. 给出每个点的标准化坐标

它真正擅长的是“视觉结构提取”，不是最终语义判断。

---

### 2.2 为什么关键点比整图分类更好

如果直接把图像喂给分类器做 `Fist / VSign / OpenPalm`，你会遇到：

- 受背景影响大
- 受光照影响大
- 受尺度影响大
- 对不同角度泛化不稳

而关键点把问题变成几何问题。

例如：

- 指尖和 PIP/MCP 的相对位置
- 食指和小指的张开距离
- 掌心中心的运动轨迹

这些量更稳定，也更适合规则和序列判断。

---

### 2.3 21 点坐标的数学意义

MediaPipe 输出的手部点本质上是一个离散点集：

`P = {p0, p1, ..., p20}`

每个点是一个二维或三维坐标，项目里大部分最终只用到二维视口坐标：

`p_i = (x_i, y_i)`

这些坐标通常被归一化到 `[0, 1]`，所以它不是像素距离，而是屏幕比例距离。

这意味着：

- `0.1` 的位移表示“屏幕宽高中的 10%”
- 不同分辨率下比较更稳定
- 便于用统一阈值做规则

---

### 2.4 Unity 原生 MediaPipe 流程

代码入口：

- `Assets/Scripts/Input/NativeMediapipeGestureRunner.cs`

它在内部做了几个关键步骤：

#### a. 图像预处理

Graph 里有 `ImageTransformationCalculator`。

它负责：

- 旋转
- 水平翻转
- 垂直翻转

这是为了把摄像头朝向和 Unity 坐标统一起来。

#### b. 手部跟踪

Graph 的核心节点是 `HandLandmarkTrackingCpu`。

它输出：

- `landmarks`
- `handedness`
- `palm detections`

#### c. 稳定化

Runner 里有：

- `candidateGesture`
- `stableGesture`
- `candidateFrames`
- `requiredStableFrames`

这是一种简单的多数/连续帧稳定机制。

如果某个姿势连续出现 `n` 帧，就认为它稳定。

数学上就是：

`stable = arg stable if count(raw == candidate) >= n`

它不是分类器，而是时间滤波器。

## 3. 静态手势的数学原理

### 3.1 静态手势就是几何分类

项目里的静态手势主要有：

- `Point`
- `Fist`
- `VSign`
- `OpenPalm`

判断逻辑依赖关键点之间的相对关系。

---

### 3.2 指头是否伸直

在 `NativeMediapipeGestureRunner.ClassifyGestureFromLandmarks` 里，核心判断函数是：

`IsFingerExtended(landmarks, tipIndex, pipIndex, mcpIndex)`

它的规则是：

`tip.y < pip.y - 0.015`
`pip.y < mcp.y - 0.005`

这是一个基于屏幕坐标系的启发式判断。

因为在项目当前坐标约定里，手往上伸时 `y` 会变小，所以：

- 指尖比 PIP 更高
- PIP 比 MCP 更高

就说明手指大概率是伸直的。

这不是严格的解剖学模型，而是一个稳健的工程规则。

---

### 3.3 Fist 的判断

如果四根手指都不伸直：

`!indexExtended && !middleExtended && !ringExtended && !pinkyExtended`

就判定为 `Fist`。

这说明识别逻辑不是“找一个拳头模板”，而是靠手指整体收拢状态判断。

---

### 3.4 V Sign 的判断

V 手势的规则大致是：

- 食指伸直
- 中指伸直
- 无名指、小指不伸直
- 食指与小指尖端距离足够大

代码里对应：

`indexExtended && middleExtended && !ringExtended && !pinkyExtended && spread > 0.12`

这里的 `spread` 是：

`distance(landmarks[8], landmarks[20])`

也就是食指指尖和小指指尖的距离。

这个距离的作用是防止“两个手指几乎并在一起”时误判成 V。

---

### 3.5 Point 的判断

如果只有食指伸直：

`indexExtended && !middleExtended && !ringExtended && !pinkyExtended`

就判定为 `Point`。

---

### 3.6 OpenPalm 的判断

如果大部分手指都伸开，并且拇指张开到一定程度：

`fingersUp >= 4 && thumbSpread > 0.09`

这里 `thumbSpread` 是拇指根部附近和掌部的距离。

这也是一个几何启发式条件，而不是神经网络分类器。

---

## 4. 动态手势的数学原理

动态手势的核心不是“这一帧像什么”，而是“这一段时间怎么动”。

---

### 4.1 统一的时间窗口

动态识别器里会维护一个历史队列：

- `handHistory`
- `poseHistory`

只保留最近 `historySeconds` 的数据。

这相当于一个滑动时间窗：

`W(t) = { samples | t - sampleTime <= historySeconds }`

这样做的好处：

- 避免旧数据污染
- 只看最近动作
- 动作检测不会无限延迟

---

### 4.2 运动量的基本计算

最常见的量有：

#### 位移

`Δx = x_last - x_first`
`Δy = y_last - y_first`

#### 距离

`d = sqrt((x2 - x1)^2 + (y2 - y1)^2)`

Unity 里大量用的是 `Vector2.Distance`，本质就是这个公式。

#### 速度

`v = distance / duration`

其中：

`duration = t_last - t_first`

---

### 4.3 Swipe 的判断

Swipe 的识别逻辑本质上是：

1. 最近几个样本的位移足够大
2. 偏离方向不能太多
3. 速度不能太低
4. 距离上次触发不能太近

在 `NativeMotionGestureRecognizer` 和 `ExternalMotionGestureRecognizer` 里都类似。

典型条件：

- `abs(horizontalDelta) >= swipeMinDistance`
- `verticalDrift <= swipeMaxVerticalDrift`
- `speed >= swipeMinSpeed`
- `last.Time - lastSwipeTime >= swipeCooldownSeconds`

这个逻辑的数学意思是：

**只承认“朝一个方向明确移动了一段距离”的动作。**

---

### 4.4 Snap 的判断

Snap 不是看整条轨迹，而是看两根手指之间的距离变化。

它的核心变量是：

`tipDistance = distance(thumbTip, middleTip)`

识别逻辑分两段：

#### 预备阶段

如果 `tipDistance <= snapCloseDistance`

就认为“啪”这个动作已经进入准备状态。

#### 释放阶段

在一定时间内，如果距离回弹到 `snapReleaseDistance` 以上，并且冷却时间已过，就触发 Snap。

这相当于一个小状态机：

- `Idle`
- `Primed`
- `Fired`

---

### 4.5 PointToFist 的判断

这个动作检测的是“姿势转变”。

逻辑要求：

- 前一状态是 Point
- 当前状态是 Fist
- 中间时间在合理范围内
- 手掌位置变化不能太大

代码条件大致是：

`previousGesture == Point`
`sample.Gesture == Fist`
`sample.Time - previousChangeTime` 在阈值内
`Vector2.Distance(sample.Palm, previousPalm) <= gestureTransitionMaxTravel`

这说明它不是判断“现在像拳头”，而是判断“从指向拳头的转变过程”。

---

### 4.6 OpenPalm Slap

这个动作本质是：

“手势保持 OpenPalm，同时手掌中心横向快速移动”

判断项包括：

- OpenPalm 占历史窗口的比例足够高
- 横向位移够大
- 竖向漂移够小
- 速度够快

公式上就是：

`abs(Δx) >= minimumDistance`
`abs(Δy) <= maximumDrift`
`abs(Δx) / duration >= minimumSpeed`

这使它成为“带姿势约束的挥动动作”。

---

## 5. YOLO + MediaPipe 的数学和工程关系

### 5.1 YOLO 在这里不是做手势分类

YOLO 在项目里负责的是“主体定位”。

它输出的是一个检测框：

`box = (x1, y1, x2, y2)`

然后系统会扩大这个框，再裁剪图像。

---

### 5.2 为什么裁剪能提高识别

如果原图是整个房间，手只占很小一部分，那么 MediaPipe 需要处理更多背景干扰。

裁剪后，输入区域更聚焦，手在图中的相对尺寸更大。

这相当于提高了信噪比。

---

### 5.3 裁剪后的坐标重映射

如果在裁剪图上识别到一点 `u,v`，要映射回原图：

`x = (x1 + u * cropWidth) / frameWidth`
`y = (y1 + v * cropHeight) / frameHeight`

这就是 `remap_landmarks_to_frame` 做的事。

这是一个非常典型的坐标系变换问题。

---

### 5.4 YOLO 的系统意义

YOLO 不是替代 MediaPipe，而是给 MediaPipe 加了前置定位。

所以整个链路是：

`YOLO -> 裁剪 -> MediaPipe -> 手势规则`

这会比直接全图识别更稳。

---

## 6. DTW 的数学原理

### 6.1 为什么需要 DTW

动态轨迹最麻烦的是“速度不一致”。

比如两个轨迹：

- 模板 A：慢慢画
- 运行 B：快速画

它们在形状上很像，但帧数不同、采样节奏不同。

如果直接逐点比较，会错得很厉害。

DTW 就是为这个问题设计的。

---

### 6.2 DTW 的核心思想

给两条序列：

- `X = x1, x2, ..., xm`
- `Y = y1, y2, ..., yn`

DTW 会建立一个 `m x n` 的代价矩阵。

每个格子的局部代价通常是：

`d(i,j) = ||xi - yj||`

然后通过动态规划求一条总代价最小的对齐路径。

递推关系是：

`D(i,j) = d(i,j) + min(D(i-1,j), D(i,j-1), D(i-1,j-1))`

这就是标准的 DTW 思想。

---

### 6.3 项目里 DTW 的实现形态

`CustomGestureTrajectoryMatcher.Score(...)` 就是在做这个事情。

它：

1. 取两条轨迹
2. 建二维代价表
3. 用局部距离 + 最优前驱递推
4. 计算最终分数

最后返回：

`cost / (rows + columns)`

这样可以把不同长度的路径放在相对统一的尺度上比较。

---

### 6.4 轨迹归一化为什么重要

如果不归一化，不同人、不同距离、不同镜头下的轨迹尺度会差很多。

所以在 `CustomGestureTrajectoryMatcher` 里先做：

#### 1. 去重

如果连续点差异太小，就丢掉。

#### 2. 平移归一化

把第一点当作原点：

`p'_i = p_i - p_0`

#### 3. 尺度归一化

再除以最大距离：

`p''_i = p'_i / maxDistance`

这样轨迹就变成“只看形状，不看绝对大小”。

#### 4. 重采样

把轨迹重新采成固定数量点，比如 32 个。

这样模板和运行轨迹就能比较了。

---

### 6.5 为什么重采样

因为 DTW 虽然能容忍速度不同，但点数差异太大时，比较成本高，模板也不稳定。

固定采样数的好处是：

- 比较稳定
- 便于存模板
- 便于在多个样本之间统一尺度

---

## 7. 自定义手势的数学原理

### 7.1 静态模板特征

`CustomGestureFeatureExtractor` 的做法是把 21 个点变成一个特征向量。

每个点都以手腕为原点：

`q_i = (p_i - p_wrist) / scale`

其中 `scale` 通常取：

- 中指 MCP 到手腕的距离
- 或食指 MCP 到小指 MCP 的掌宽

这一步的作用是做尺度归一化。

最终得到：

`feature = [x0, y0, x1, y1, ..., x20, y20]`

也就是一个长度 42 的向量。

---

### 7.2 静态模板的距离

静态模板比较时，本质是在算欧氏距离：

`dist(a,b) = sqrt(sum((a_i - b_i)^2) / N)`

也就是均方根风格的距离。

距离越小，说明越像。

---

### 7.3 动态模板的规则推断

`CustomGestureDynamicRuleEvaluator` 会从样本里推断动态规则。

它看的是：

- 总时长
- 轨迹长度
- 终点和起点距离
- 闭合程度
- 方向翻转次数
- 横向/纵向偏移

这些统计量会组合成几个评分：

- `DirectionScore`
- `RepeatScore`
- `ClosedLoopScore`

然后根据阈值决定模板更像：

- 方向型
- 重复型
- 闭环型

---

### 7.4 方向型动态规则

判断条件核心是：

- 总位移足够大
- 横向或纵向漂移不过大
- 方向符合预设方向

数学上就是：

`NetDistance >= minimumDistance`
`PerpendicularDrift <= maximumDrift`

---

### 7.5 重复型动态规则

重复型动作更像左右摆动、来回摆动。

关键量是：

- `DirectionFlipCount`
- 路径长度
- 总位移

如果方向反转次数达到要求，就视为重复型。

---

### 7.6 闭环型动态规则

闭环型动作类似画圈。

判断条件是：

- 起点和终点距离小
- 总路径长度明显大于闭合距离

也就是：

`closureDistance <= maxClosureDistance`
`pathRatio >= minimumPathRatio`

其中：

`pathRatio = pathLength / closureDistance`

如果路径绕了一大圈最后回到附近，`pathRatio` 就会比较大。

---

## 8. 阈值为什么存在

很多新手会疑惑：为什么代码里这么多 `0.09`、`0.12`、`0.45`？

原因很简单：

### 8.1 手势识别本质上不是纯理论问题

它是工程问题。

这些阈值本质是在平衡三件事：

- 灵敏度
- 稳定性
- 误触发率

---

### 8.2 阈值的角色

#### 距离阈值

控制“动作够不够大”。

#### 速度阈值

控制“动作够不够快”。

#### 漂移阈值

控制“动作是不是纯净”。

#### 时间阈值

控制“动作持续是否合理”。

#### 冷却阈值

控制“是否重复触发”。

---

### 8.3 为什么这些值不是完美常数

因为它们不是数学真理，而是：

- 采样率相关
- 摄像头相关
- 人体差异相关
- 识别策略相关

所以这类项目里，阈值只能靠实验调参逼近最好结果。

---

## 9. 代码层面的状态机思想

### 9.1 Snap 的状态机

可以理解为：

- `Idle`
- `Primed`
- `Triggered`

这就是为什么它不会一闪就触发。

---

### 9.2 GestureInputRouter 的路由状态

它在不同输入模式之间切换：

- `Mock`
- `NativeMediapipe`
- `ExternalBridge`

本质上是一个模式路由器。

---

### 9.3 施法确认状态

`GestureSpellCaster` 里有：

- `pendingSpell`
- `PendingProgress`
- `lastCastSpell`
- `statusHoldUntil`

这就是一个施法确认状态机：

1. 识别到候选法术
2. 保持一段时间
3. 进度条满了才施放
4. 施放后进入短暂保持

---

## 10. 你应该怎么真正读懂这套系统

如果想从底层真正理解，不要先看游戏效果，先看这四个层级：

### 第一层：点是什么

看关键点坐标、归一化、坐标系翻转。

### 第二层：几何关系是什么

看伸直、张开、距离、速度、漂移。

### 第三层：时间结构是什么

看窗口、冷却、稳定帧、历史命令。

### 第四层：语义怎么落地

看映射、组合、施法、移动、菜单。

---

## 11. 最后一句话

MediaPipe 给你“手的骨架”，YOLO 给你“人的位置”，DTW 给你“轨迹相似性”，规则系统给你“动作含义”，Unity 给你“游戏行为”。

这套项目的核心价值，不是某一个算法单独有多强，而是它把这些技术按层次接起来了。
