# 符印守卫 非核心系统实现说明

## 1. 范围

本说明聚焦除关卡设计、法术实现、手势识别之外的“非核心系统”内容，主要包括：

- 设置系统
- UI 流程与状态反馈
- 基础属性与计算层
- 运行时流程控制

## 2. 设置系统

当前设置系统已具备以下能力：

- 施法确认时长切换
- 敌人节奏切换
- 菜单停留确认时长
- 菜单返回长按时长

当前通过 `SpellGuardGameSettings` 统一管理，并由 `SpellGuardMenuOverlay` 与 `SpellGuardFlowController` 消费。

## 3. UI 流程与反馈

当前 UI 流程已具备：

- 主菜单
- 设置页
- 教程页
- 训练页
- 结果页

并已具备：

- 焦点切换
- 确认触发
- 返回逻辑
- 最近确认反馈
- HUD 状态显示

## 4. 属性与计算层

当前已开始从硬编码转为配置与计算抽象：

- `SpellConfig`
- `SpellConfigLibrary`
- `EnemyConfig`
- `DifficultySettings`

现阶段目标不是复杂数值系统，而是先把：

- 法术效果参数
- 敌人基础参数
- 难度参数

统一收束到清晰的配置入口中。

当前已完成的最小落地内容包括：

- 法术效果从散落硬编码开始收束为统一配置读取
- 敌人基础属性从控制器内部提炼为基础配置结构
- 难度切换从直接写死数值转为统一难度参数结构

## 5. 当前结论

- 非核心系统已经具备继续扩展和收口的基础。
- 这些内容已足以支撑答辩版的流程、反馈和基础系统完整性。
- 当前剩余问题更多集中在内容层和手感层，而不是基础流程与属性组织层。
