# 符印守卫 答辩版 vs 比赛版功能边界表

## 1. 使用说明

- 本表用于冻结范围，避免开发持续扩散。
- “答辩版”优先保证 5 分钟内可稳定展示完整闭环。
- “比赛版”在答辩版基础上扩展完整游戏感和表现力。

## 2. 功能边界表

| 模块 | 答辩版 | 比赛版 |
|---|---|---|
| 主交付平台 | Unity 版 | Unity 版 |
| 菜单 / 设置 / 训练 / 战斗 / 结算闭环 | 必须完成 | 保留并强化 |
| 至少一个纯手势驱动 UI 交互界面 | 必须完成 | 保留并扩展 |
| Mock / Native / External 三模式 | 至少可切换且不阻断流程 | 保持并优化稳定性 |
| 第一关教学关 | 必须完成 | 保留并优化 |
| 第二关策略关 | 可有简化版 / 演示版 | 建议完整实现 |
| 第三关高潮关 | 可只保留概念或轻量雏形 | 建议完整实现 |
| 四向固定距离移动 | 必须完成 | 保留并调优 |
| 辅助视角与锁定切换 | 必须完成 | 保留并优化 |
| 三个基础法术 | 必须完成 | 保留并强化表现 |
| 动态手势高光展示 | 至少一种可演示 | 建议扩展到多种 |
| 双手手势 | 可作为展示预告 / 雏形 | 建议做到可用展示状态 |
| 敌人差异化 | 至少 2~3 类可看出分工 | 建议扩到完整 4 类 |
| 命中 / 受击 / 护盾反馈 | 基础版可用 | 建议显著强化 |
| Build Settings / 打包 | 建议完成 | 必须完成 |
| 论文支撑图表 | 必须完成 | 保留 |
| 比赛包装视频 / 封面 / 文案 | 可后置 | 必须完成 |

## 3. 答辩版必须冻结的内容

- 以“菜单 -> 教学关 -> 第一关 -> 结算”作为最小完整闭环
- 不为了追求关卡数量而牺牲稳定性
- 不为了追求炫技而引入大量高风险输入扩展
- 不为了比赛包装提前扩张到超出原型承载能力的内容

## 4. 比赛版可追加的内容

- 第二关和第三关的完整化
- 双手手势高光玩法
- 更多动态手势
- 更强的敌人分层
- 更完整的美术包装与演示镜头
- 更完整的可执行打包版本

## 5. 当前建议

- 答辩版以稳定闭环为第一优先级
- 比赛版以内容拓展和表现强化为第一优先级
- 如果某项内容既影响稳定性又不直接提升答辩闭环，应默认推迟到比赛版
