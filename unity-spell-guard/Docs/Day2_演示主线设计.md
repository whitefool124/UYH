# Day 2 演示主线设计

## 1. 菜单 -> 教学 -> 战斗 -> 结算主线

推荐把答辩版的演示主线固定为以下顺序：

1. 进入开始界面
2. 用手势进入模式说明 / 教学说明
3. 进入教学关
4. 完成基础移动、基础施法、基础 UI 认知
5. 进入第一关正式战斗
6. 完成推进式遭遇战目标 / 到达出口或下一节点
7. 进入胜利或失败结算页
8. 展示返回菜单或重开

这条主线的目标不是“把所有内容全讲完”，而是让评审在最短时间内看到完整闭环：

- 纯手势菜单交互
- 纯手势四向移动与施法
- 地图推进 / 遭遇战 / 结算
- 反馈界面与系统状态可视化

## 2. 三关结构设计

### 第一关：教学关

定位：建立“全手势闭环”认知。

内容：

- 菜单手势导航
- Point 控视角与前进意图
- Fist / V / OpenPalm 三种基础法术
- 动态手势至少展示一种高辨识动作
- 低压推进式遭遇
- 明确出口或完成节点

核心目的：

- 让玩家和评审理解“这不是识别演示，而是可玩的输入系统”

推荐时长：

- 1.5 ~ 2 分钟

### 第二关：策略关

定位：展示“空间判断 + 法术选择”的关系。

内容：

- 更明确的敌人差异
- 路线或区域差异
- 让火 / 冰 / 盾用途区别清晰
- 让玩家产生换位、拉距、控场判断

核心目的：

- 证明玩法不是原地站桩施法，而是要做位置、推进路径和时机决策

推荐时长：

- 1.5 分钟

### 第三关：高潮关

定位：展示项目上限与完整游戏感。

内容：

- 多波敌人或 Boss 压力
- 危险区域 / 终局任务 / 核心守卫目标
- 动态手势和双手手势的高光展示时机
- 更快节奏的移动、施法、保命切换

核心目的：

- 让评审看到项目具备进一步扩展为完整作品的潜力

推荐时长：

- 1.5 分钟

## 3. 每关展示目的与时长

| 关卡 | 展示重点 | 推荐时长 |
|---|---|---|
| 第一关：教学关 | 全手势闭环、基础交互、基础反馈 | 1.5 ~ 2 分钟 |
| 第二关：策略关 | 空间决策、法术用途区分、关卡推进 | 1 ~ 1.5 分钟 |
| 第三关：高潮关 | 动态动作、节奏压力、完整游戏感 | 1 ~ 1.5 分钟 |

## 4. 5 分钟答辩演示路线

### 第 0 分钟 ~ 第 0.5 分钟

- 简要介绍项目定位：纯手势驱动的第一人称施法原型
- 说明输入来源支持 Mock / Native / External

### 第 0.5 分钟 ~ 第 1 分钟

- 进入开始界面
- 用手势完成一次 UI 选择
- 展示“纯手势驱动 UI 交互”这一核心卖点

### 第 1 分钟 ~ 第 2.5 分钟

- 进入教学关
- 演示：
  - 四向移动、辅助视角与目标锁定切换
  - 三种基础法术
  - 至少一个动态手势
  - HUD / 动态动作反馈板

### 第 2.5 分钟 ~ 第 4 分钟

- 进入第一关或策略关
- 展示空间推进、敌人压力、法术切换、锁定切换和护盾保命

### 第 4 分钟 ~ 第 5 分钟

- 展示结算页
- 展示返回菜单 / 重开
- 收尾强调：
  - 识别链路
  - 输入抽象层
  - 游戏化闭环已经成立

## 5. Day 2 结论

- 答辩主线优先以“菜单 -> 教学关 -> 第一关 -> 结算”作为最小完整闭环。
- 三关结构可以继续做，但答辩版必须先保证第一关的推进式遭遇战闭环稳定。
- 第二关和第三关主要服务于比赛版强化与完整作品表达。
- 当前移动方案已冻结为四向固定距离移动，并配合辅助视角转动和锁定切换手势。
- 涉及手势输入的功能允许先用键鼠做临时实现方案，只要不破坏后续替换路径。
- 五关故事结构当前优先做临时可跑通版本，而不是一开始追求全部正式化。
