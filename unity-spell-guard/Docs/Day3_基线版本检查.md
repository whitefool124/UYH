# Day 3 基线版本检查

## 1. 检查目标

Day 3 的目的不是新增功能，而是确认当前 Unity 原型是否具备继续往教学关和正式关卡推进的稳定基础。

本次检查聚焦以下四项：

1. 原型场景启动流程
2. 输入模式切换
3. 移动 / 施法 / 敌人 / HUD 当前状态
4. 当前问题清单 V1

## 2. 原型场景启动流程检查

### 2.1 当前基线流程

根据 `README.md` 和 `CreatePrototypeScene.cs`，当前推荐启动流程为：

1. 在 Unity Hub 中打开 `unity-spell-guard/`
2. 等待导入完成
3. 执行菜单 `Spell Guard/Create Prototype Scene`
4. 打开 `Assets/Scenes/SpellGuardPrototype.unity`
5. 点击 Play

### 2.2 当前状态判断

- 原型场景生成链路存在
- `CreatePrototypeScene` 已经承担显式装配入口角色
- 场景生成相关 EditMode 测试已跟随重构同步

### 2.3 结论

- 启动流程基线成立
- 当前版本可继续以 `CreatePrototypeScene` 作为统一原型场景入口

## 3. 输入模式切换检查

### 3.1 当前输入模式

`GestureInputRouter` 当前支持三种模式：

- `Mock`
- `NativeMediapipe`
- `ExternalBridge`

### 3.2 切换方式

- 当前默认仍通过 `F1` 在运行时循环切换模式

### 3.3 当前状态判断

- 三模式抽象仍然成立
- Router 仍是统一输入出口
- Mock 模式仍是当前最稳定的开发和答辩兜底链路

### 3.4 结论

- 输入模式切换基线成立
- 但从答辩和最终交互设计角度看，后续应评估是否继续保留 `F1` 作为主切换方式，或将其收敛为开发调试手段

## 4. 移动 / 施法 / 敌人 / HUD 检查

### 4.1 移动

当前 `FpsGestureMotor` 已进入四向离散移动改造阶段：

- `Point` 用于前进意图与辅助视角
- 左右动态动作用于横向换位
- `OpenPalm` 承担防御性后撤语义

### 4.2 施法

当前 `GestureSpellCaster` 仍然是基于：

- 静态手势确认释放
- 动态手势直接触发释放

基础三法术逻辑仍可工作：

- 火焰术
- 冰霜术
- 护盾术

### 4.3 敌人

当前 `EnemySpawner` 仍以基础生成逻辑为主：

- 生成简单 Capsule 原型敌人
- 根据难度控制刷新节奏和数量

### 4.4 HUD

当前 `DebugHud` 和 `SpellGuardMenuOverlay` 已完成第一轮结构拆分：

- Flow / UI / 状态数据开始分层
- HUD 仍然偏重，但已进入可继续拆解状态

### 4.5 结论

- 施法、敌人和 HUD 的基线可以继续支撑后续开发
- 当前最大不一致点在于：

**策划层已经冻结为“四向固定距离移动 + 辅助视角 + 锁定切换”，运行时代码已开始向离散步进逻辑迁移，但仍需完成完整输入映射与运行时验证。**

这说明 Day 4 之前，必须优先解决移动系统实现与策划方案不一致的问题。

## 5. 问题清单 V1

### P0 问题

1. 移动方案尚未完全闭环
   - 策划文档已冻结为四向固定距离移动
   - 当前 `FpsGestureMotor` 已开始离散步进改造，但还需完整手势映射、数值验证和 HUD/交互同步

2. 纯手势 UI 方案与当前运行时菜单仍不一致
   - 文档方向已经从“指向式光标”转向“离散焦点切换”
   - 当前原型中的部分设计思路仍带有旧版 Point 主导痕迹

### P1 问题

3. `DebugHud` 仍偏重
   - 已完成第一轮重构，但后续还需继续收口

4. 敌人仍处于原型替代状态
   - 当前只是基础战斗体，还没有真正体现追击 / 冲刺 / 压制 / 护甲的玩法差异

5. Build Settings 仍为空
   - 当前还未进入正式打包阶段

### P2 问题

6. 双手手势与更多动态手势仍停留在文档与优先级层
7. 五关结构已成文档，但尚未转成逐关可玩内容

## 6. Day 3 结论

- 原型项目的启动流程、输入抽象层、施法逻辑、敌人刷新和 HUD 基线是可继续开发的。
- 当前最关键的问题不是“系统是否存在”，而是“系统实现是否已经与新策划冻结方案统一”。
- 后续开发优先级建议：

1. 先完成移动系统的离散化闭环，使其完全符合四向固定距离移动方案
2. 再按新的关卡与 UI 方案推进教学关搭建
3. 保持 Mock 兜底链路可用，确保答辩演示稳定
