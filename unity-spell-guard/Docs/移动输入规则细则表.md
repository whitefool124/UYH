# 符印守卫 移动输入规则细则表

## 1. 设计目标

- 把当前已冻结的“四向固定距离移动 + 辅助视角 + 锁定切换”落实成可执行输入规则。
- 保证输入简单、可记忆、低疲劳、低冲突。
- 在正式手势输入未完全稳定前，允许用键盘 / 鼠标做临时实现与验证。

## 2. 当前冻结方案

### 2.1 基础移动

- 前进一步
- 后退一步
- 左移一步
- 右移一步

每次移动都是固定距离，不做连续摇杆式推进。

### 2.2 非独立输入

- 不再设计独立左转手势
- 不再设计独立右转手势
- 不再设计独立回头手势

### 2.3 辅助系统

- 辅助视角转动
- 锁定目标切换

## 3. 推荐输入映射

| 功能 | 推荐输入 | 说明 |
|---|---|---|
| 前进一步 | `Point` 前进确认 | 主要推进方式 |
| 后退一步 | `OpenPalm` 防御性后撤 | 与保命语义统一 |
| 左移一步 | 左向动态动作 | 用于换位、拉距、闪避 |
| 右移一步 | 右向动态动作 | 用于换位、拉距、闪避 |
| 辅助视角转动 | `Point` 引导视角 + 系统自动修正 | 不要求持续手动控镜头 |
| 锁定切换 | 独立锁定切换手势 | 在多个威胁目标间切换 |

## 4. 输入优先级建议

### 4.1 同时存在冲突时

建议优先级：

1. 系统层确认 / 返回
2. 锁定切换
3. 四向移动输入
4. 基础静态施法
5. 高阶动态施法

### 4.2 原则

- 同一时间尽量只允许玩家表达一种主要意图
- 如果已经进入 UI 选择状态，则移动输入应暂时失效
- 如果已经进入法术确认状态，则导航输入不应频繁打断

## 5. 触发规则建议

### 5.1 前进一步

- 触发方式：`Point` 后短确认
- 建议用途：推进、靠近目标点、通过狭路

### 5.2 后退一步

- 触发方式：`OpenPalm` 防御性确认
- 建议用途：后撤、拉开距离、脱离危险格

### 5.3 左移 / 右移一步

- 触发方式：左右动态动作
- 建议用途：横向换位、躲避压制、重新选角度

### 5.4 锁定切换

- 触发方式：单独手势，不与基础法术重叠
- 建议用途：切换当前威胁目标，降低纯视角控制压力

## 6. 防误触建议

- 所有移动输入都应有短冷却
- 同一方向输入不要在极短时间内重复触发多次
- 锁定切换手势应明显区别于基础施法动作
- 后撤与护盾语义如果重叠，需在系统层明确哪个优先

## 7. 当前待确认项

- `Point` 前进是否采用停留确认还是单次触发
- `OpenPalm` 后撤与护盾是否完全分离
- 锁定切换具体使用静态姿势还是动态动作
- 每一步固定距离、输入冷却与缓冲窗口数值

## 8. 临时实现原则

- 如果某个移动手势当前识别还不稳定，可先用键盘按键映射相同语义完成验证。
- 临时键鼠方案只作为开发和调试兜底，不改变最终纯手势目标。
- 临时实现必须保持和最终输入语义一一对应，避免后续重做整套关卡逻辑。
