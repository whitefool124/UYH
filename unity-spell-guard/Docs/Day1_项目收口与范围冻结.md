# Day 1 项目收口与范围冻结

## 1. 结论

- Unity 版 `unity-spell-guard/` 确认为当前阶段最终主交付。
- 浏览器端 MVP 保留为早期验证分支成果，不再作为答辩主演示版本。
- 当前后续开发、演示、论文支撑、比赛包装均以 Unity 版为主线。

## 2. P0 / P1 / P2 功能清单

### P0：必须完成

- 菜单 -> 教学/战斗 -> 结果页的完整可演示闭环
- 至少一个完全由手势驱动的 UI 交互界面达到可稳定演示状态
- Mock / NativeMediapipe / ExternalBridge 三种输入模式至少可切换且不阻断流程
- 玩家基础移动、基础施法、敌人生成、生命与护盾逻辑可运行；涉及手势输入的部分允许键鼠作为临时实现方案
- 教学关与至少一条完整答辩演示路线可稳定走通
- HUD / MenuOverlay / MotionGestureFeedbackBoard 能提供必要的状态反馈
- Runtime / Editor / EditModeTests / PlayModeTests 编译通过

### P1：强烈建议完成

- 三关结构中的第一关与第二关可试玩
- 法术用途区分更明确（火 / 冰 / 盾）
- 关键命中、受击、护盾、动态动作提示更完整
- 双手手势输入能力进入可演示状态
- 在现有动态手势基础上扩展更多可稳定展示的动作
- Build Settings、打包与非开发环境运行验证
- 论文支撑图表、模块结构图、输入链路图整理完成

### P2：可选增强

- 第三关高潮段 / Boss 压力设计完全落地
- 更复杂的路线分支、空间危险与多波敌人
- 更完整的比赛包装与额外展示视频

## 3. 答辩版与比赛版共用内容

### 共用基础

- Unity 项目主体
- 手势输入抽象层
- 菜单、训练、战斗、结算流程
- 第一人称施法战斗原型
- HUD 与动态动作反馈
- Editor 场景生成工具
- 训练集验证工具
- 自动化测试与技术文档

### 答辩版优先目标

- 5 分钟内可稳定展示完整闭环
- 强调“纯手势输入 -> 游戏命令 -> 实时玩法反馈”
- 以教学关 + 第一关 + 结算页为主

### 比赛版优先目标

- 在答辩版基础上强化完整游戏感
- 增加第二关 / 第三关、战斗反馈、节奏层次与包装表现
- 补充视频、简介、创新点和更强的关卡展示

### 当前实现原则补充

- 任何涉及手势输入但短期难以稳定落地的功能，允许先用键盘 / 鼠标做临时实现，以保证关卡和流程能跑通。
- 五关结构当前优先做“临时可跑通版本”，先验证节奏、结构和流程，再逐步替换成正式内容。
