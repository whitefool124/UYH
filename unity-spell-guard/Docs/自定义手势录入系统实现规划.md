# 自定义手势录入系统实现规划

## 1. 文档目的

本文档用于下一轮开发 `CustomGesture` 自定义手势录入与识别功能。目标不是在代码中继续手写更多固定手势枚举，而是让使用者可以在 Unity 训练界面录入自己的新手势样本，并由系统在运行时识别这些样本，再映射到现有 `GestureIntent / GestureAction` 意图层。

本功能应服务毕业设计展示：证明项目从“固定手势识别”扩展到“用户可录入的新手势模板识别”，同时不破坏当前菜单、训练、移动、战斗已经建立的意图层架构。

## 2. 硬约束

实现时必须继续遵守 `Docs/符印守卫_手势设计规范.md` 中的硬约束：

- 不新增依赖手部屏幕坐标、手指指向、光标命中、区域点选的玩法输入。
- 不新增依赖 Pose Landmark、身体左移/右移、躯干倾斜、站位偏移的玩法输入。
- 不把 `Point` 作为新增菜单、移动、施法或训练步骤的核心输入。
- 自定义手势仅使用单手 21 个 hand landmarks、时间戳、置信度、左右手信息。
- 识别结果必须输出为 `GestureAction` 或可映射到 `GestureIntent`，玩法系统不得直接消费自定义模板原始数据。

## 4. 推荐方案

采用“模板录入 + 本地模板匹配”的轻量方案，不引入深度学习训练流程。

### 4.1 静态自定义手势

适合：稳定姿势类手势。

识别方式：

1. 从当前 `GestureFrame.PrimaryHand.Landmarks` 采样。
2. 将 21 个点转换为归一化特征向量。
3. 与已保存模板做距离比较。
4. 距离低于阈值且连续稳定若干帧后触发。

### 4.2 动态自定义手势

适合：挥动、画圈、捏合后打开等短时间动作。

识别方式：

1. 录入 0.8 到 1.5 秒的 landmark 序列。
2. 每帧提取归一化特征。
3. 运行时维护短滑动窗口。
4. 用 DTW 或固定长度重采样后的序列距离做模板匹配。
5. 低于阈值时输出自定义动作。

第一版建议优先做动态模板，因为它最能体现“我录入一个新动作，系统能识别出来”的展示价值。

## 5. 数据结构设计

### 5.1 CustomGestureTemplate

建议新增文件：

- `Assets/Scripts/Input/CustomGestureTemplate.cs`

建议字段：

```csharp
public enum CustomGestureKind
{
    StaticPose,
    DynamicMotion
}

public sealed class CustomGestureTemplate
{
    public string GestureId;
    public string DisplayName;
    public CustomGestureKind Kind;
    public GestureIntent TargetIntent;
    public float MatchThreshold;
    public List<CustomGestureSample> Samples;
}
```

### 5.2 CustomGestureSample

建议字段：

```csharp
public sealed class CustomGestureSample
{
    public string SampleId;
    public GestureHandedness Handedness;
    public float DurationSeconds;
    public List<CustomGestureFrameSample> Frames;
}
```

### 5.3 CustomGestureFrameSample

建议字段：

```csharp
public sealed class CustomGestureFrameSample
{
    public float Time;
    public float Confidence;
    public Vector2[] Landmarks;
}
```

### 5.4 保存位置

第一版保存为 JSON：

```text
Application.persistentDataPath/CustomGestures/{gestureId}.json
```

不要保存到 `训练集/`，因为该目录是外部数据集验证路径，不是玩家运行时录入模板路径。

## 6. Landmark 归一化

新增文件建议：

- `Assets/Scripts/Input/CustomGestureFeatureExtractor.cs`

归一化规则：

1. 如果没有 21 个 landmarks，当前帧无效。
2. 以 wrist 或 palm center 为原点，将所有点平移到局部坐标。
3. 用掌宽或 wrist 到 middle MCP 的距离做尺度归一化。
4. 第一版可不做旋转归一化，先通过阈值与多样本容错；第二版再增加手掌方向对齐。
5. 输出固定长度 `float[]` 特征向量。

拒识规则：

- landmark 数量不足：拒识。
- confidence 低于阈值：拒识。
- 手离开画面：中断录制或匹配。
- 匹配分数高于阈值：拒识。

## 7. 运行时模块设计

### 7.1 CustomGestureRecorder

新增文件：

- `Assets/Scripts/Input/CustomGestureRecorder.cs`

职责：

- 从 `GestureInputProviderBase.CurrentGestureFrame` 读取当前主手 landmarks。
- 管理录制状态：Idle、Countdown、Recording、Review、Saved。
- 按固定采样间隔保存帧。
- 过滤无效帧。
- 输出 `CustomGestureSample`。

第一版只需要支持：开始录制、取消录制、保存样本。

### 7.2 CustomGestureLibrary

新增文件：

- `Assets/Scripts/Input/CustomGestureLibrary.cs`

职责：

- 从 persistentDataPath 加载模板 JSON。
- 保存模板 JSON。
- 删除模板。
- 提供 `IReadOnlyList<CustomGestureTemplate>` 给识别器。

### 7.3 CustomGestureRecognizer

新增文件：

- `Assets/Scripts/Input/CustomGestureRecognizer.cs`

职责：

- 维护最近一段 `GestureFrame` 滑动窗口。
- 对静态模板做最近邻匹配。
- 对动态模板做序列匹配。
- 匹配成功后输出 `GestureAction`。

接口建议：

```csharp
public bool TryResolve(GestureFrame frame, out GestureAction action)
```

或：

```csharp
public GestureAction CurrentCustomAction { get; }
```

### 7.4 接入 GestureInputProviderBase

可在 `GestureInputProviderBase` 增加虚拟属性：

```csharp
public virtual GestureAction CurrentCustomAction => GestureAction.None;
```

更推荐第一版不改 provider 派生类，而是在场景中新增 `CustomGestureRuntime` MonoBehaviour，绑定 `GestureInputProviderBase`，由它读取 frame 并输出自定义 action。这样改动范围更小。

## 8. UI 流程设计

入口放在 Training 页面，不放在战斗中。

### 8.1 第一版 UI 状态

在训练页新增一个“自定义手势录入”分支：

1. 选择“录入新手势”。
2. 输入或循环选择名称：`Custom 1 / Custom 2 / Custom 3`。
3. 选择目标意图：先只允许 `CastFire / CastIce / CastShield` 三个之一。
4. 倒计时 3 秒。
5. 录制 1.2 秒。
6. 显示本次样本是否有效。
7. 录满 5 个有效样本后保存模板。
8. 进入测试模式：玩家做动作，识别成功则显示“识别到 Custom X”。

### 8.2 为什么第一版只绑定三法术

只绑定 `CastFire / CastIce / CastShield` 可以避免菜单、移动、训练流程被自定义手势打乱，也更容易验收。后续再扩展到 `MenuConfirm`、`MoveLeft` 等系统意图。

## 9. 不做内容

第一版明确不做：

- 不做可视化轨迹编辑器。
- 不做云端训练。
- 不做神经网络训练。
- 不做身体姿态模板。
- 不做 Point 区域选择模板。
- 不做多人共享模板库。
- 不做复杂手势命名输入法；名称可先用预设编号。

## 10. 实施步骤

### Step 1：数据模型与 JSON 保存

新增：

- `CustomGestureTemplate.cs`
- `CustomGestureLibrary.cs`

验收：

- 可以创建一个模板对象。
- 可以保存到 persistentDataPath。
- 可以重新加载。
- 空模板、坏 JSON 不会导致崩溃。

### Step 2：特征提取

新增：

- `CustomGestureFeatureExtractor.cs`

验收：

- 21 点输入可以输出固定长度特征。
- 少于 21 点返回失败。
- 同一手势在平移/缩放后特征距离保持较小。

### Step 3：录制器

新增：

- `CustomGestureRecorder.cs`

验收：

- 从 `CurrentGestureFrame` 录制 1.2 秒样本。
- 无手、低置信度、landmark 不足时样本无效。
- 样本包含时间序列和 landmarks。

### Step 4：识别器

新增：

- `CustomGestureRecognizer.cs`

验收：

- 加载一个动态模板后，重复相似动作可以输出对应 `GestureAction`。
- 不相似动作不会触发。
- `Point` 或 `BodyShift` 不会作为自定义触发条件。

### Step 5：训练界面接入

修改：

- `SpellGuardMenuOverlay.cs`
- `SpellGuardFlowController.cs`

验收：

- Training 页可以进入录制流程。
- 可以录满 5 个样本并保存。
- 测试模式可以显示识别结果。
- 返回菜单/训练不会卡住输入状态。

### Step 6：战斗接入

修改：

- `GestureSpellCaster.cs`

验收：

- 自定义手势映射到 `CastFire / CastIce / CastShield` 后可触发对应法术。
- 普通 Fist/VSign/OpenPalm 仍然可用。
- 自定义识别有冷却，不能一帧重复触发多次。

## 11. 测试计划

建议新增 PlayMode 测试：

- `CustomGestureFeatureExtractorTests.cs`
  - 验证 landmark 归一化与无效输入。
- `CustomGestureLibraryTests.cs`
  - 验证 JSON 保存、加载、坏文件容错。
- `CustomGestureRecorderTests.cs`
  - 验证录制状态机和样本有效性。
- `CustomGestureRecognizerTests.cs`
  - 验证模板匹配、拒识、冷却。
- `CustomGestureFlowTests.cs`
  - 验证训练页录入流程不会破坏现有训练完成门槛。

必须保留或新增的安全测试：

- Point 不作为自定义手势主条件。
- BodyShift 不参与自定义模板识别。
- 低置信度 landmarks 不触发自定义 action。
- 空模板库不会影响普通施法。

## 12. 验收标准

第一版完成条件：

1. 用户可以在 Training 页录制一个自定义动态手势。
2. 系统至少保存 5 个有效样本到本地 JSON。
3. 重新进入场景后模板可以加载。
4. 用户重复该动作时，识别器输出绑定的 `GestureAction`。
5. 绑定到 `CastFire / CastIce / CastShield` 后，战斗中能触发对应法术。
6. Unity 编译 0 错误。
7. LSP diagnostics 0 新错误。
8. 相关 PlayMode/EditMode 测试通过。
9. 手动 QA 证明：录制、保存、重新加载、识别、触发法术完整闭环可跑通。

## 14. 推荐实现顺序

如果时间有限，严格按以下顺序做：

1. 数据模型 + JSON 保存/加载。
2. Landmark 归一化 + 单元测试。
3. Recorder 只录样本，不接 UI。
4. Recognizer 用手写模板测试跑通。
5. Training UI 接入录制。
6. SpellCaster 接入识别结果。

不要先做复杂 UI。先证明数据闭环和识别闭环，再做交互 polish。
