# 符印守卫 移动手势映射表

## 1. 设计目标

- 支撑四向固定距离移动
- 降低移动手势数量与学习成本
- 保持纯手势交互闭环
- 避免导航手势与施法手势高频冲突

## 2. 当前冻结方案

### 2.1 核心原则

- 玩家不进行连续摇杆式移动
- 玩家每次输入的是“移动意图”，不是持续推杆
- 地面和关卡空间应配合四向离散位移
- 视角转动由辅助系统和 `Point` 引导完成

### 2.2 正式映射表

| 功能 | 推荐手势 | 说明 | 优先级 |
|---|---|---|---|
| 前进一步 | `Point` 向前 / 前进确认 | 作为主要推进动作 | P0 |
| 后退一步 | `OpenPalm` 防御性后撤语义 | 保留防御 / 后撤统一感 | P0 |
| 左移一步 | 左向动态动作（左挥 / 左侧拨） | 紧急换位和横移 | P0 |
| 右移一步 | 右向动态动作（右挥 / 右侧拨） | 紧急换位和横移 | P0 |
| 辅助视角转动 | `Point` 控视角 / 锁定辅助修正 | 不单独设计左右转向手势 | P0 |
| 锁定切换 | 独立锁定切换手势 | 用于切换当前关注目标 | P0 |

## 3. 取消的旧方向

以下方案在当前版本中不再采用：

- 独立左转手势
- 独立右转手势
- 独立回头手势
- 长时间持续摇杆式前进

原因：

- 增加学习成本
- 容易和施法手势冲突
- 提高手势疲劳与误触风险
- 不符合当前线性推进与房间制关卡结构

## 4. 输入分层建议

### 4.1 系统层手势

- 用于菜单、设置、确认、进入关卡

### 4.2 导航层手势

- 用于四向位移
- 用于辅助视角
- 用于锁定切换

### 4.3 战斗层手势

- 用于基础三法术

### 4.4 高阶层手势

- 用于动态手势强化释放
- 用于双手手势扩展

## 5. 设计约束

- 同一时间只鼓励玩家处理一类主要输入意图
- 导航手势必须在教学关里被单独介绍
- 任何新增导航手势都必须证明它比现有方案更必要
- 如果移动方案需要持续高频输入，应优先回退到当前冻结方案而不是继续复杂化

## 6. 后续待确认项

- 前进一步是否采用短停留确认还是直接触发
- 后退一步是否完全由 `OpenPalm` 负责，还是另设更明确的后撤动作
- 锁定切换手势最终采用静态姿势还是动态动作
- 四向位移的格距、冷却和输入缓冲窗口
