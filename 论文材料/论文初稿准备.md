# 《面向体感游戏的动态手势轨迹跟踪方法实现》论文初稿准备稿

## 1. 当前项目结论

当前仓库已经具备支撑毕业论文初稿的主体材料。主交付应以 `unity-spell-guard/` Unity 工程为准，根目录浏览器端 MVP 可作为早期方案验证或技术路线演进背景，不建议作为论文主实现。

项目的核心优势是已经形成了较完整的“视觉输入/手势输入 -> 运行时抽象 -> 动态动作识别 -> 游戏命令 -> Unity 玩法反馈”链路，并配有技术文档、策划文档、训练集校验工具和基础自动化测试。论文可以围绕该链路展开，而不是只写一个静态手势识别 demo。

## 2. 技术栈与工程证据

### 2.1 Unity 与依赖

- Unity 版本：`2022.3.62f2c1`。
- 关键依赖：
  - `com.github.homuler.mediapipe`：本地 tgz 形式接入的 MediaPipe Unity 包。
  - `com.unity.test-framework`：Unity 自动化测试。
  - `com.unity.ugui`：菜单、HUD 与运行时反馈界面。
  - `com.unity.timeline`、`com.unity.visualscripting`：Unity 常规扩展能力。
  - `com.besty.unity-skills`、`com.anklebreaker.unity-mcp`：本地/ Git 依赖，主要影响复现环境。
- Build Settings 已包含 `Assets/Scenes/SpellGuardPrototype.unity`。

### 2.2 主要工程模块

- `Assets/Scripts/Input/`：手势帧、命令、历史、序列匹配、Mock / Native MediaPipe / ExternalBridge 输入源。
- `Assets/Scripts/Core/`：启动装配、流程控制、设置、运行状态、场景上下文。
- `Assets/Scripts/Player/`：基于手势的移动与施法。
- `Assets/Scripts/Combat/`：敌人生成、生命值、护盾、法术配置。
- `Assets/Scripts/UI/`：HUD、菜单 Overlay、动态手势反馈板。
- `Assets/Editor/`：原型场景生成、训练集验证工具。
- `Assets/Tests/`：EditMode / PlayMode 测试，覆盖场景生成、数据集验证、输入适配、动作识别、序列匹配、流程控制等。

## 3. 与任务书/开题报告的一致性

任务书要求围绕“面向体感游戏的动态手势轨迹跟踪方法实现”，重点包括：

1. 结合 YOLO 检测与 MediaPipe 姿态估计技术；
2. 构建普通 RGB 摄像头下的实时动态手势交互体感游戏；
3. 解决视觉算法与 Unity 引擎的集成问题；
4. 体现鲁棒性、低延迟和游戏交互闭环；
5. 具备模块化设计、版本控制、单元测试和系统测试。

当前项目与这些要求基本匹配，尤其在 Unity 集成、动态手势事件、外部 UDP 桥接、Mock 兜底、场景生成和测试方面证据较强。需要注意的是，当前仓库中“完整 YOLO 训练与 LSTM 时序模型”不是最强证据，应在论文中谨慎表述为：系统设计参考 YOLO/MediaPipe 融合路线，工程实现重点落在 MediaPipe/外部桥接关键点序列、时序规则识别、命令抽象与 Unity 闭环验证。若最终未补充 YOLO 训练实验，不应在论文中声称已完成独立 YOLO 模型训练与 95% 准确率实验。

## 4. 稳定性与可靠性评估

### 4.1 可以支撑论文的稳定点

- 工程结构清晰，Runtime / Editor / EditModeTests / PlayModeTests 有程序集边界。
- 输入系统有三种模式：`Mock`、`NativeMediapipe`、`ExternalBridge`。
- `Mock` 模式可作为答辩和论文截图的稳定兜底链路。
- `NativeMediapipe` 和 `ExternalBridge` 可展示真实视觉链路与外部数据流接入能力。
- 动态手势离线基线文档证明外部 UDP landmark replay 可以产生 swipe / snap 类事件。
- 场景生成、输入适配、动态识别、序列匹配、训练集校验均有测试或文档证据。

### 4.2 当前主要风险

| 风险 | 影响 | 建议 |
|---|---|---|
| Native MediaPipe 与摄像头依赖运行环境 | 答辩机器可能出现初始化、权限、驱动问题 | 保持 Mock 默认启动；提前在答辩设备测试 Native 模式 |
| 本地 tgz / 本地 package / Git package 依赖 | 换机复现可能失败 | 固定依赖文件，记录 Unity 版本与导入步骤 |
| YOLO 训练实验证据不足 | 论文算法贡献可能被质疑 | 论文口径收束到融合架构与交互闭环；若有时间再补充小规模 YOLO/外部检测实验 |
| 第一关/多关内容仍未完全落地 | “完整游戏性”论证不足 | 初稿先写系统与原型验证，关卡内容作为应用场景与后续完善 |
| 真实性能指标尚未系统统计 | 无法强写“毫秒级/95%准确率” | 补充 FPS、端到端延迟、误触率、任务完成率等可测指标 |

### 4.3 总体判断

项目“稳定可靠支持论文初稿”是成立的；“稳定可靠支持最终答辩”还需要完成一次环境验证、测试截图、运行截图、性能指标记录和演示兜底脚本。论文初稿可以立即开始，但应避免把尚未实测的算法指标写成最终结论。

## 5. 论文初稿建议题目与定位

建议沿用任务书题目：

《面向体感游戏的动态手势轨迹跟踪方法实现》

论文定位建议写成：

本文面向普通 RGB 摄像头下的体感游戏交互场景，设计并实现一种面向 Unity 游戏引擎的动态手势轨迹跟踪与命令映射系统。系统以 MediaPipe 手部关键点和外部视觉桥接数据为基础，结合动态轨迹规则、命令历史和序列匹配，将连续手势转换为可被游戏逻辑消费的交互命令，并在《符印守卫》Unity 原型中完成实时施法、移动、菜单与反馈闭环验证。

## 6. 初稿章节框架

### 第 1 章 绪论

- 研究背景：体感游戏、人机交互、普通 RGB 摄像头降低部署成本。
- 问题定义：动态手势存在速度差异、空间轨迹差异、抖动、遮挡、误触与游戏实时性要求。
- 研究目标：构建实时动态手势轨迹跟踪与 Unity 游戏交互闭环。
- 主要工作：输入感知、时序识别、命令映射、Unity 原型、测试验证。

### 第 2 章 相关技术与研究现状

- 体感游戏应用现状。
- 视觉手势识别方法：传统视觉、CNN/YOLO、MediaPipe、YOLO-Pose。
- 动态手势轨迹建模：关键点序列、速度、方向、时间窗、序列匹配。
- 游戏交互中的评价指标：准确率、误触率、延迟、FPS、任务完成率。

### 第 3 章 系统需求与总体设计

- 应用场景：《符印守卫》纯手势施法游戏。
- 功能需求：菜单、训练、战斗、结算、施法、移动、反馈。
- 非功能需求：实时性、鲁棒性、可扩展性、可测试性、演示容错。
- 总体架构：输入源、手势帧、命令层、动作识别、玩法消费、UI 反馈。

### 第 4 章 动态手势轨迹跟踪与命令识别方法

- 手部关键点数据结构：`GestureFrame`、`TrackedHandState`、`ExternalVisionFrame`。
- 静态姿态识别与稳定确认。
- 动态动作识别：滑动、Snap、PointToFist、OpenPalmSlap 等。
- 命令历史与序列匹配：时间窗、顺序约束、组合动作。
- 多输入源统一：Mock、Native MediaPipe、ExternalBridge。

### 第 5 章 Unity 游戏原型实现

- Unity 工程结构与版本依赖。
- 场景生成与启动装配：`CreatePrototypeScene`、`SpellGuardSceneContext`、`SpellGuardBootstrap`。
- 玩法模块：移动、施法、敌人、生命与护盾。
- UI 与反馈：HUD、菜单 Overlay、动态手势反馈板。
- 训练集验证与外部 UDP 回放流程。

### 第 6 章 测试与实验分析

- 单元/PlayMode/EditMode 测试说明。
- 动态手势离线回放基线：IPN clips、UDP packet、swipe/snap 事件。
- 系统测试：Mock / Native / External 三模式对比。
- 建议补充实验指标：FPS、端到端延迟、手势触发成功率、误触率、任务完成时间。
- 风险与误差分析：光照、遮挡、快速动作、个体差异、摄像头位置。

### 第 7 章 总结与展望

- 总结系统实现成果。
- 总结工程与实验验证。
- 展望：YOLO 检测增强、LSTM/Transformer 时序模型、双手手势、更多关卡、用户研究。

## 8. 初稿写作原则

- 不要夸大尚未完成的 YOLO 训练、LSTM 模型和 95% 准确率。
