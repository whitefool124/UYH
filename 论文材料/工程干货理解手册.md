# 工程干货理解手册：真正理解你做的系统

这份文档不按答辩话术写，而按“工程系统到底怎么跑”来写。目标是让你理解自己做的东西：数据从哪里来、经过哪些类、怎么变成动作、为什么这样设计、哪里容易出问题、怎么调参、怎么扩展。

---

## 1. 你的系统本质上是什么

这个项目不是单纯的“识别手势”，而是一个输入系统。

它做的事情是：

```text
原始输入
  -> 视觉/模拟数据
  -> 手势帧
  -> 手势命令
  -> 交互意图
  -> 游戏行为
  -> HUD / 战斗 / CSV / 测试
```

其中最关键的是中间三层：

```text
GestureFrame
GestureCommand
GestureAction / GestureIntent
```

这三层把“我看到了什么”和“游戏应该做什么”分开了。

如果没有这几层，游戏代码就会直接依赖摄像头、MediaPipe 关键点或 UDP 报文。那样一换输入源，玩家移动、施法、菜单都要改。

现在你的设计是：

```text
不管数据来自 Mock、Native MediaPipe 还是 ExternalBridge，
游戏层都只消费统一的动作意图。
```

这就是系统的真正价值。

## 2. 运行时完整数据流

完整链路可以拆成 7 步。

### 第 1 步：输入源产生数据

三种输入源：

```text
MockGestureInputProvider
NativeMediapipeGestureProvider
ExternalGestureBridgeProvider
```

它们都继承：

```text
GestureInputProviderBase
```

这意味着它们必须对外提供统一接口，例如：

```text
CurrentSnapshot
CurrentGestureFrame
CurrentGestureCommand
CurrentMotionGesture
RecentGestureCommands
CurrentSpellAction
CurrentMovementAction
GetMenuAction()
```

这就是面向对象里“统一抽象”的实际用法。

### 第 2 步：输入源转换为 Snapshot / Frame

早期或兼容层使用 `GestureSnapshot` 表示单手基础状态：

```text
HandPresent
Gesture
ViewportPosition
Confidence
```

更完整的运行时结构是 `GestureFrame`：

```text
FrameId
Timestamp
Source
Hands
LatestMotion
```

一个 `GestureFrame` 可以包含多个 `TrackedHandState`，虽然当前主线基本按单手处理，但结构上已经为多手扩展留了位置。

### 第 3 步：动态识别器产生 MotionGestureEvent

动态动作不是输入源天然就有的。

Native 链路由：

```text
NativeMotionGestureRecognizer
```

External 链路由：

```text
ExternalMotionGestureRecognizer
```

它们负责维护历史样本队列，识别：

```text
Swipe
Snap
PointToFist
OpenPalmSlap
BodyShift
```

识别到以后调用 provider 的：

```text
PushMotionGesture(...)
```

把动作塞回输入提供者。

### 第 4 步：Frame / Motion 转成 GestureCommand

这个转换由：

```text
LegacyGestureRuntimeAdapter.BuildCommand(snapshot, motion)
```

完成。

逻辑很关键：

```text
如果 motion 有效，优先返回 Motion 命令
否则返回 StaticPose 命令
```

也就是说动态动作优先级高于静态手势。

为什么？

因为一次滑动过程中，手可能一直处于 OpenPalm 或 Point 状态。如果不优先处理 Motion，游戏会被静态手势干扰。

### 第 5 步：GestureCommand 转成 GestureIntent

命令还不是最终玩法。

`GestureIntentMapper` 会根据场景把命令解释成意图：

```text
菜单意图
施法意图
移动意图
训练意图
```

例如：

```text
Fist -> CastFire
Fist -> MenuConfirm
OpenPalm -> CastShield
OpenPalm -> MenuBack
SwipeLeftToRight -> MoveRight
SwipeLeftToRight -> MenuPrevious
```

同一个手势在不同上下文下可以有不同含义。

### 第 6 步：游戏模块消费 Intent

几个主要消费者：

```text
FpsGestureMotor
GestureSpellCaster
SpellGuardStartMenuController
SpellGuardFlowController
DebugHud
```

它们不关心 MediaPipe 怎么识别，也不关心 UDP 怎么传输，只关心：

```text
现在玩家想移动吗？
现在玩家想施法吗？
现在玩家想确认菜单吗？
```

### 第 7 步：反馈和记录

游戏行为发生后，系统通过：

```text
HUD
MotionGestureFeedbackBoard
GesturePerformanceMonitor
DemoRunRecorder
CSV 导出
```

提供反馈和实验数据。

## 3. Base Class：GestureInputProviderBase 是核心接口

`GestureInputProviderBase` 是所有输入源的共同基类。

它的意义是给上层一个统一合同。

关键接口：

```text
CurrentSnapshot
CurrentMotionGesture
CurrentGestureFrame
CurrentGestureCommand
CurrentCustomAction
CurrentSpellAction
CurrentMovementAction
CurrentComboAction
RecentGestureCommands
GetMenuAction(bool allowBack)
ClearTransientInputs()
```

理解方式：

```text
输入源负责提供“当前状态”。
上层不用知道这个状态来自哪里。
```

例如玩家移动模块只需要：

```text
inputProvider.CurrentGestureFrame
```

施法模块只需要：

```text
inputProvider.CurrentSpellAction
```

菜单模块只需要：

```text
inputProvider.GetMenuAction(...)
```

这就是为什么系统能切换三种输入模式。

## 4. MockGestureInputProvider：模拟输入不是摆设

Mock 的代码逻辑很清楚：

```text
Tab          切换 handPresent
Alpha0      None
Alpha1      Point
Alpha2      Fist
Alpha3      VSign
Alpha4      OpenPalm
LeftArrow   SwipeRightToLeft
RightArrow  SwipeLeftToRight
UpArrow     SwipeBottomToTop
DownArrow   SwipeTopToBottom
Enter       PointToFist
J/L/I/K     移动 viewportPosition
```

它内部也有：

```text
GestureCommandHistory
latestMotionGesture
currentGestureCommand
motionEventTimeout
```

说明 Mock 不是简单键盘映射，而是模拟完整输入 provider 行为。

### 4.1 Mock 的真正作用

Mock 负责验证：

- 命令层是否工作；
- GestureIntentMapper 是否工作；
- 玩家移动是否工作；
- 施法是否工作；
- 菜单是否工作；
- CSV 导出是否工作；
- 自动化测试是否能稳定运行。

它不负责证明：

- MediaPipe 识别准确；
- 摄像头链路鲁棒；
- 外部视觉算法准确。

### 4.2 为什么 Mock 也要维护命令历史

因为上层逻辑需要 `RecentGestureCommands`。

如果 Mock 没有命令历史，那么组合动作、训练流程或调试逻辑在 Mock 下就无法验证。

这就是工程一致性：

```text
Mock 虽然是假输入，但对外行为要像真输入。
```

## 5. ExternalGestureBridgeProvider：外部桥接怎么跑

ExternalBridge 是最复杂也最有工程价值的一条链路。

### 5.1 外部帧进入 Unity

外部程序把数据包装成：

```text
ExternalVisionFrame
```

调用或通过 UDP 进入 Unity 后，provider 执行：

```text
PushFrame(frame)
```

`PushFrame` 做了这些事：

1. 保存 `currentFrame`；
2. `frameVersion++`；
3. 记录 `lastPacketTime`；
4. 统计包间隔；
5. 把 frame 放入 `pendingFrames`；
6. 转换 hand landmarks；
7. 转换 pose landmarks；
8. 解析 handedness；
9. 解析 gesture 字符串；
10. 生成 snapshot；
11. 刷新 GestureFrame；
12. 刷新 GestureCommand；
13. 记录命令历史。

这就是为什么 ExternalBridge 可以同时支持：

- HUD 状态显示；
- 动态识别；
- 性能统计；
- 延迟估计；
- 回放实验。

### 5.2 pendingFrames 是干什么的

`ExternalMotionGestureRecognizer` 不是直接读取 `CurrentFrame`，而是：

```text
while (bridgeProvider.TryDequeuePendingFrame(out var frame))
{
    ProcessFrame(frame);
}
```

也就是说外部帧先进队列，动态识别器逐帧消费。

这样做的好处：

- 不丢掉短时间内到达的帧；
- 能按帧顺序处理；
- 适合离线回放；
- 动态识别有连续样本。

### 5.3 超时机制

ExternalBridge 有两个超时：

```text
snapshotTimeout = 0.25s
motionEventTimeout = 1.2s
```

如果太久没收到外部帧：

- snapshot 清空；
- currentFrame 清空；
- landmarks 清空；
- pendingFrames 清空；
- commandHistory 清空。

为什么要这样？

如果外部程序停止发送，Unity 不能一直认为“手还在”。否则玩家离开画面后，游戏还会继续响应旧手势。

### 5.4 BridgeStatus

`BridgeStatus` 有三种：

```text
Waiting
Receiving
Stale
```

解释：

- `Waiting`：还没收到过 frame；
- `Receiving`：最近收到 frame；
- `Stale`：收过 frame，但现在超时了。

这对调试非常重要。

## 6. NativeMotionGestureRecognizer：Unity 内部动态识别

Native 链路处理 Unity 内部 MediaPipe 的结果。

### 6.1 它每帧怎么工作

Update 中：

```text
如果 nativeProvider 为空，返回
如果 FrameVersion 没变化，返回
否则 ProcessCurrentFrame()
```

这说明它不会重复处理同一帧。

### 6.2 当前帧处理逻辑

`ProcessCurrentFrame()` 主要步骤：

1. 读取 `CurrentSnapshot`；
2. 如果没有手，ResetState；
3. 构造 `HandSample`；
4. 做抖动过滤；
5. 加入历史队列；
6. 修剪超出 0.7 秒的旧样本；
7. 依次尝试：
   - GestureTransition；
   - OpenPalmSlap；
   - Swipe；
   - Snap。

顺序也有意义：

- 状态转换优先；
- 张掌扇动优先于普通滑动；
- 滑动优先于响指；
- 识别到部分动作后会重置历史，避免重复触发。

### 6.3 HandSample 包含什么

```text
Time
Palm
ThumbTip
MiddleTip
Gesture
HasSnapData
```

一个样本就是“某一时刻手的位置和状态”。

掌心估计：

```text
palm = (landmarks[0] + landmarks[5] + landmarks[17]) / 3
```

响指点：

```text
ThumbTip = landmarks[4]
MiddleTip = landmarks[12]
```

## 7. ExternalMotionGestureRecognizer：外部回放动态识别

External 识别器和 Native 类似，但多了人体姿态。

它维护两个队列：

```text
handHistory
poseHistory
```

手部队列用于：

- Swipe
- Snap

姿态队列用于：

- BodyShiftLeft
- BodyShiftRight

### 7.1 为什么 External 支持 BodyShift

因为 ExternalVisionFrame 可以带：

```text
poseLandmarks
```

而 Native 当前主线主要关注手部关键点。

External 的灵活性就在这里：外部程序可以提供更多视觉信息，例如人体姿态、YOLO 检测结果、离线视频标签等。

### 7.2 BodyShift 怎么计算

使用四个姿态点：

```text
左肩 11
右肩 12
左髋 23
右髋 24
```

计算：

```text
shoulderCenter = (leftShoulder + rightShoulder) / 2
hipCenter = (leftHip + rightHip) / 2
bodyCenter = (shoulderCenter + hipCenter) / 2
```

再看 bodyCenter 在历史窗口内是否横向移动。

## 8. LegacyGestureRuntimeAdapter：兼容层但很关键

这个类名字里有 Legacy，但它实际承担关键转换。

### 8.1 BuildSingleHandFrame

它把旧式 snapshot 变成新式 GestureFrame。

如果没检测到手：

```text
Hands = empty
LatestMotion = motion
```

如果检测到手：

```text
创建一个 TrackedHandState
填入 StaticGesture、Confidence、ViewportPosition、PalmCenter、Landmarks
```

### 8.2 BuildCommand

核心逻辑：

```text
if motion.IsValid:
    return GestureCommand.FromMotion(motion)
else:
    return GestureCommand.FromStatic(snapshot)
```

这句非常重要。

它决定了系统当前命令优先选择动态动作。

例子：

玩家做向右滑动时，当前手势可能仍是 OpenPalm，但系统优先输出：

```text
Motion: SwipeLeftToRight
```

而不是：

```text
StaticPose: OpenPalm
```

## 9. GestureIntentMapper：真正的语义层

这是你系统最容易被忽视但很有价值的一层。

`GestureCommand` 只说明：

```text
玩家做了什么手势
```

`GestureIntent` 说明：

```text
这个手势在当前上下文里意味着什么
```

### 9.1 菜单映射

静态：

```text
Fist -> MenuConfirm
OpenPalm -> MenuBack
```

动态：

```text
SwipeLeftToRight -> MenuPrevious
SwipeRightToLeft -> MenuNext
Snap -> MenuConfirm
PointToFist -> MenuConfirm
```

### 9.2 施法映射

静态：

```text
Fist -> CastFire
VSign -> CastIce
OpenPalm -> CastShield
```

动态：

```text
Snap -> CastFire
PointToFist -> CastFire
```

### 9.3 移动映射

动态：

```text
SwipeRightToLeft -> MoveLeft
SwipeLeftToRight -> MoveRight
SwipeBottomToTop -> MoveForward
SwipeTopToBottom -> MoveBackward
```

静态：

```text
OpenPalm -> MoveBackward
```

### 9.4 训练映射

训练不关心具体是左滑还是右滑，只关心玩家完成了滑动类动作：

```text
Swipe / OpenPalmSlap -> TrainingSwipe
Snap / PointToFist -> TrainingSpecialConfirm
```

这说明同一个底层命令可以被不同系统重新解释。

## 10. FpsGestureMotor：手势怎么变成移动

玩家移动模块叫：

```text
FpsGestureMotor
```

它做的是离散步进移动，不是连续摇杆式移动。

### 10.1 为什么用离散步进

体感手势不适合每帧连续控制方向，否则容易受抖动影响。

离散步进的逻辑是：

```text
检测到一次有效动作
  -> 朝某个方向移动固定距离
```

参数：

```text
moveStepDistance = 1.5
moveStepDuration = 0.18s
moveInputCooldown = 0.18s
horizontalMoveCooldown = 0.45s
verticalMoveCooldown = 0.45s
```

### 10.2 每帧流程

Update 中：

1. 读取 `inputProvider.CurrentGestureFrame`；
2. 提取主手状态；
3. 如果输入启用，处理离散移动；
4. 如果正在步进，用 `Vector3.Lerp` 平滑移动；
5. 应用重力；
6. 调用 `CharacterController.Move`。

### 10.3 动态动作移动

调用：

```text
GestureIntentMapper.ToMovementAction(frame)
```

得到：

```text
MoveLeft
MoveRight
MoveForward
MoveBackward
```

然后调用：

```text
BeginStep(direction)
```

### 10.4 静态动作移动

OpenPalm 可以映射成后退。

但它不是一出现就后退，而是需要保持：

```text
staticMoveHoldSeconds = 0.25s
```

为什么？

因为静态手势容易持续存在，如果一检测到就反复移动，会失控。

所以系统要求保持一段时间，并且消费一次后不重复触发。

## 11. GestureSpellCaster：手势怎么变成施法

施法模块叫：

```text
GestureSpellCaster
```

它有两种施法方式：

1. 动态手势立即触发；
2. 静态手势需要确认时间。

### 11.1 动态手势施法

动态动作是 transient，也就是瞬时动作。

例如：

```text
Snap -> CastFire
PointToFist -> CastFire
```

只要它的触发时间比上次处理时间新，就立即施法。

代码里用：

```text
lastHandledMotionTime
```

避免同一个动态动作被处理多次。

### 11.2 静态手势施法

静态手势需要确认：

```text
confirmSeconds = 0.4s
```

例如：

```text
Fist -> CastFire
VSign -> CastIce
OpenPalm -> CastShield
```

流程：

1. 检测到手势；
2. 进入 pendingSpell；
3. 显示确认进度；
4. 保持到 100%；
5. Cast。

为什么要确认？

因为静态手势可能短暂误识别，直接施法会误触。

### 11.3 施法结果

Fire：

- 发射火球 projectile；
- projectile 有速度、生命周期、伤害。

Ice：

- 射线检测敌人；
- 命中后 ApplyFreeze。

Shield：

- 调用 PlayerHealth.ActivateShield。

## 12. 为什么要分 GestureCommand 和 GestureIntent

这是工程设计里的精华。

如果只有 GestureCommand：

```text
Fist
OpenPalm
SwipeLeftToRight
```

游戏模块还要自己判断：

- 在菜单里 Fist 是确认；
- 在战斗里 Fist 是火焰；
- 在训练里 Fist 是完成动作；
- OpenPalm 有时是后退，有时是护盾，有时是返回。

这样每个模块都要写一套映射，容易重复和混乱。

所以引入：

```text
GestureIntentMapper
```

统一把命令变成场景意图。

这让设计更清楚：

```text
GestureCommand = 玩家做了什么
GestureIntent = 当前系统认为玩家想干什么
Gameplay = 游戏如何执行这个意图
```

## 13. 动态识别参数怎么调

### 13.1 Swipe 调参

如果滑动太难触发：

- 降低 `swipeMinDistance`
- 降低 `swipeMinSpeed`
- 增大 `historySeconds`

如果误触太多：

- 提高 `swipeMinDistance`
- 提高 `swipeMinSpeed`
- 减小 `swipeMaxVerticalDrift`
- 增大 `swipeCooldownSeconds`

### 13.2 Snap 调参

如果响指难触发：

- 增大 `snapCloseDistance`
- 降低 `snapReleaseDistance`
- 增大 `snapMaxDuration`

如果误触太多：

- 降低 `snapCloseDistance`
- 增大 `snapReleaseDistance`
- 减小 `snapMaxDuration`
- 增大 `snapCooldownSeconds`

### 13.3 PointToFist 调参

如果太难触发：

- 增大 `gestureTransitionMaxDuration`
- 增大 `gestureTransitionMaxTravel`

如果误触太多：

- 减小 `gestureTransitionMaxDuration`
- 减小 `gestureTransitionMaxTravel`
- 增大 `pointHoldMinDuration`

### 13.4 BodyShift 调参

如果身体移动难触发：

- 降低 `bodyShiftMinDistance`
- 降低 `bodyShiftMinSpeed`
- 降低 `minPoseVisibility`

如果误触太多：

- 提高 `bodyShiftMinDistance`
- 提高 `bodyShiftMinSpeed`
- 提高 `minPoseVisibility`
- 减小 `bodyShiftMaxVerticalDrift`

## 14. 系统最脆弱的地方

### 14.1 摄像头环境

Native MediaPipe 受：

- 光照；
- 背景；
- 摄像头角度；
- 手部遮挡；
- 运动模糊；
- 权限和驱动；
- 插件初始化。

### 14.2 阈值规则泛化

规则方法依赖阈值。

不同人动作快慢、幅度不同，可能导致：

- 触发不了；
- 触发错方向；
- 多次触发；
- 静态和动态动作冲突。

### 14.3 ExternalBridge 链路

ExternalBridge 依赖：

- 外部程序是否启动；
- UDP 是否发送；
- 数据格式是否正确；
- timestamp 是否合理；
- Unity 是否及时消费 pendingFrames。

### 14.4 语义映射冲突

同一个手势在不同上下文有不同含义。

如果流程状态管理不清楚，可能出现：

- 菜单里触发施法；
- 战斗里触发菜单动作；
- 训练动作被战斗逻辑消费。

你的系统通过不同模块调用不同 mapper 方法来降低这个风险：

```text
GetMenuAction
CurrentSpellAction
CurrentMovementAction
ToTrainingAction
```

## 15. 如果你要扩展一个新动作，怎么做

假设要新增一个“画圈 Circle”动作。

步骤大概是：

1. 在 `MotionGestureType` 增加：

```text
Circle
```

2. 在 Native 或 External 识别器中维护轨迹，判断是否接近圆形。

3. 识别成功后调用：

```text
PushMotionGesture(MotionGestureType.Circle, position, confidence)
```

4. 在 `GestureIntentMapper` 中决定它的意义：

## 20. 学习时你要能回答的硬问题

### 数据从 ExternalBridge 到施法经过哪些类？

```text
ExternalVisionFrame
-> ExternalGestureBridgeProvider.PushFrame
-> ExternalMotionGestureRecognizer.ProcessFrame
-> PushMotionGesture
-> GestureCommand
-> GestureIntentMapper.ToSpellAction
-> GestureSpellCaster.TryCastFromAction
-> Cast
```

### 数据从 Native MediaPipe 到移动经过哪些类？

```text
NativeMediapipeGestureProvider
-> NativeMotionGestureRecognizer
-> MotionGestureEvent
-> GestureFrame
-> GestureIntentMapper.ToMovementAction
-> FpsGestureMotor.HandleDiscreteMovement
-> BeginStep
-> CharacterController.Move
```

### 为什么 GestureCommand 要优先 Motion？

因为动态动作通常发生在静态手势之上。如果不优先 Motion，滑动、响指等瞬时动作容易被当前静态姿态覆盖。

### 为什么静态施法要确认 0.4 秒？

为了减少单帧误识别导致的误施法。

### 为什么移动用 step 而不是连续速度？

因为手势输入不像键盘长按或摇杆，连续控制容易受抖动影响。步进移动更稳定、可控、适合离散手势。

### 为什么 ExternalBridge 要有 pendingFrames？

为了按顺序消费外部帧，保证动态识别有连续历史，而不是只看最后一帧。

### 为什么命令历史要去重？

静态手势可能连续很多帧保持不变，如果每帧都记录，会污染序列匹配和组合动作判断。
